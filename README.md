# 城市宠物寄养与上门喂养服务预约管理系统

基于 Spring Boot + Vue 的城市宠物寄养与上门喂养服务预约管理平台，覆盖宠主、宠托师、管理员三角色全流程：宠物档案、服务预约、自动计价、智能匹配、寄养入住、服务报告、遛狗轨迹、健康提醒与经营数据大屏。

## 技术架构
- 后端：Spring Boot 3.3.5 + Java 21 + Spring Security + JWT + Spring Data JPA + MySQL 8
- 前端：Vue 3 + Vite + Element Plus + Pinia + Vue Router（Hash）+ ECharts
- 部署：前端构建产物由后端静态托管，单 jar 运行；systemd 服务名 `pet-app`，公网经 Cloudflare 隧道以 8080 对外（SERVER_PORT drop-in 覆盖），本地开发默认 8082

## 功能模块（15）
1. 用户与权限：注册/登录/JWT，三角色菜单与接口鉴权、数据隔离、个人中心
2. 宠物档案：多宠管理（品种/年龄/体重/绝育/疫苗/过敏/性格/喂养习惯/定点医院）
3. 服务项目：上门喂猫/喂狗、遛狗、门店寄养、家庭寄养、洗护、陪玩、喂药护理 + 附加服务，按次/按天明码标价
4. 宠托师管理：资质认证、服务区域、擅长品种、评分、接单量、接单开关、个人档案
5. 寄养空间：6 种空间，占用网格可视化 + 在住宠物列表，入住/退房联动占用
6. 预约订单：状态流转校验（待确认→已确认→已接单→服务中→已完成/已取消/已退款）；**自动计价 = 基础价×天数(次数) + 附加服务，节假日系数 1.5，长住折扣（≥7天9折、≥15天8折），多宠折扣（第2只起8折），优惠券抵扣**，价格明细存单可查
7. 入住管理：寄养入住登记/退房结算，占用 +1/−1，满房拦截下单与入住（防超卖）
8. 服务报告：喂食/换水/铲屎/陪玩/洗护清单 + 食欲/精神/排泄/体温 + 图文备注，寄养每日日报
9. 遛狗轨迹（特色）：轨迹点序列、Haversine 距离/配速计算，订单详情 SVG 轨迹回放动画
10. 智能匹配（特色）：区域(30) + 评分(30) + 擅长品种(20) + 接单量(10) + 距离(10) 综合打分，Top3 + 推荐理由
11. 价格试算器（特色）：下单页实时试算，明细逐项展示
12. 健康档案与提醒（特色）：疫苗/驱虫/体检/体重记录，30 天内到期自动提醒，体重趋势折线
13. 评价管理：订单完成可评（1–5 星+标签），计入宠托师评分，管理员可隐藏
14. 优惠券：满减/折扣券发放、领取、下单抵扣，未使用/已使用/已过期状态
15. 支付流水与公告消息：模拟支付/退款流水、平台公告、订单站内消息

## 可视化
- 仪表盘：近 30 天订单/营收双轴趋势、服务类型分布、宠物种类分布、宠托师 TOP5、订单状态分布、寄养入住率
- 寄养空间占用网格、预约日历（月视图+每日订单）、遛狗轨迹回放、体重趋势

## 游客浏览与双登录入口
平台前台支持**免登录游客浏览**，登录/注册按角色拆成两套入口：
- **游客访问**：未登录打开站点直接进入前台首页，可自由浏览前台首页、服务商城、服务详情、找宠托师、寄养空间、公开评价与平台公告；点击「立即预约 / 选 TA 预约 / 预订 / 领券 / 我的宠物 / 我的订单」等需要身份的动作时，自动跳转客人登录页并携带回跳地址，登录成功后回到原页面继续操作（下单预选参数不丢失）
- **客人入口**（前台暖橙商城风）：`/login` 与 `/register`，只服务宠主（注册仍只注册宠主）；若用员工/管理员账号在此登录，会被拒绝并提示改走管理端入口
- **管理端入口**（深色简洁办公风，无注册入口）：`/admin/login`，供管理员与宠托师登录；若用宠主账号在此登录，会被提示改走前台登录。该入口不进前台导航，仅在前台页脚有低调的「员工/管理入口」文字链
- 退出与会话过期按端分流：前台退出回前台首页（游客态），后台退出/过期回 `/admin/login`，前台过期回客人登录页并带回跳
- **游客公开接口**（`GET /api/public/**`，仅 GET 免登录）：`services`、`services/{id}`、`sitters`、`spaces`、`reviews`、`notices`、`coupons`、`overview`（服务数/宠托师数/平均评分/累计订单数/空间数/累计销量）。宠托师公开数据走脱敏 DTO（仅昵称、头像与档案公开字段，**不含手机号/邮箱/用户名**）；评价仅展示未隐藏评价的昵称等公开信息；用户密码字段为 WRITE_ONLY，任何接口都不返回密码哈希。其余接口（下单、宠物、订单、上传、支付、后台）保持登录鉴权不变

## 宠主商城前台（OWNER）
宠主登录后进入独立的商城式前台（顶栏导航、无侧边栏），与管理员/宠托师的后台彻底分开：
- **前台首页**：Hero 大图 + 服务搜索、分类瓷砖、限时领券条、热门服务、服务保障、精选宠托师、寄养空间、宠主评价、平台公告、智能匹配入口
- **服务商城**：分类 Tab 筛选、关键词搜索、按销量/价格排序，商品卡片（封面/价格起/已售量/热门标签），点击看详情或直接预约（自动预选服务）
- **找宠托师**：智能匹配打分推荐 Top3（带头像与推荐理由）、区域筛选与评分/接单量/距离排序、卡片式选 TA 预约
- **寄养空间**：照片卡片 + 剩余位置角标 + 占用进度条，预订自动带入对应寄养服务与空间
- 我的宠物（照片卡片）、我的订单/详情、预约下单、健康提醒、优惠券、公告消息、个人中心均在前台内打开；宠主访问后台地址会自动回到前台
- 管理员 / 宠托师登录后仍进入原后台（侧边栏布局 + 数据仪表盘）

## 图片与上传
- 宠物、用户头像、服务封面、寄养空间、服务报告均已改为**真实照片**展示（emoji 仅作无图时兜底）。种子照片按品种/对象配对（金毛、英短、布偶、柯基、柴犬等），存放在后端 `static/img/`（`/img/**` 静态托管，随 jar 发布），来源为公开图库检索下载后本地化，不依赖外链图床
- **上传接口**：`POST /api/upload`（需登录，multipart 表单字段 `file`），校验扩展名与文件头（jpg/png/webp）、大小 ≤ 5MB，文件存入 `uploads/yyyy-MM/` 目录并返回 `/uploads/**` 可访问 URL（静态放行读取）
- 前端通用上传组件（预览/删除/更换、多图）已接入：宠物照片、个人头像、用户管理头像、宠托师头像、服务封面、空间照片、服务报告照片（多张）
- 已上线数据库由 `ImageBackfill` 启动任务自动回填存量记录的图片字段，不影响既有订单等业务数据

## 数据库
16 张表：sys_user、pet、service_item、sitter_profile、boarding_space、booking_order、checkin_record、service_report、walk_track、health_record、review、coupon、user_coupon、payment、notice、message。结构见 `sql/schema.sql`（JPA 自动建表，种子数据由 DataInitializer 初始化）。

## 启动方式
```bash
# 1. 准备 MySQL 数据库 pet_db 与应用用户（密码写入项目根目录 .env，勿提交）
# 2. 后端打包
cd backend && mvn package -DskipTests
# 3. 前端构建并托管（已集成时可跳过）
cd frontend && npm install && npm run build && cp -r dist/* ../backend/src/main/resources/static/
# 4. 运行（Java 需加 -Djava.net.preferIPv4Stack=true）
java -Djava.net.preferIPv4Stack=true -jar backend/target/pet-system-1.0.0.jar
# 或使用 systemd：sudo systemctl start pet-app
```
访问：http://localhost:8082/
