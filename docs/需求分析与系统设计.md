# 城市宠物寄养与上门喂养服务预约管理系统 — 需求分析与系统设计

> 调研日期：2026-11-11。调研对象：呗宠、来宠、没有之一（国内上门喂养平台）、Rover/Wag 模式、Time To Pet / RoxyReserve / Collar / Book'n'Buddy（国外宠物照护 SaaS），及美团宠物寄养搜索数据报道。

## 一、需求分析（调研结论）

### 1. 行业痛点
- 节假日/出差高峰寄养需求暴涨（美团「宠物寄养」搜索环比 +150%），门店空位、宠托师档期靠微信/电话台账管理，极易冲突和遗漏。
- 宠主核心焦虑是「看不见、不放心」：服务是否真实上门、喂没喂、宠物状态如何，必须靠图文报告、打卡、轨迹来建立信任。
- 上门喂养定价不透明：按宠物类型/数量/距离/节假日浮动（市场价约 30–100 元/次，节假日加价），需要系统自动计价。
- 寄养有准入门槛：疫苗未齐、传染病宠物不可寄养，需要宠物健康档案前置校验。

### 2. 竞品共性功能（本系统全部覆盖）
宠物档案（品种/年龄/体重/疫苗/过敏/性格/喂养习惯）、服务项目与明码标价、按区域/评分筛选宠托师、在线预约下单、订单状态全流程跟踪（接单→出发→到达→服务中→完成）、服务报告（喂食/换水/铲屎/陪玩清单+图文）、寄养每日日报、评价体系、优惠券、平台担保支付流水、宠托师排班与可预约日历、容量/笼位管理、消息通知。

### 3. 竞品差异化功能（本系统做成特色）
GPS 遛狗轨迹、智能匹配宠托师、寄养空间实时占用可视化、疫苗/驱虫到期提醒、经营数据可视化大屏。

## 二、系统设计

### 技术栈
Spring Boot 3.3.5 + Java 21 + Spring Security + JWT + JPA + MySQL 8；Vue 3 + Vite + Element Plus + Pinia + Vue Router + ECharts；前端构建产物由后端静态托管（与宿舍系统同模式）。本地运行端口 8082（不影响公网宿舍系统 8080）。

### 角色（3 种）
| 角色 | 说明 | 核心权限 |
|---|---|---|
| ADMIN 管理员 | 平台/门店运营 | 全部模块、用户与宠托师审核、服务定价、寄养空间、数据大屏、公告 |
| OWNER 宠主 | 宠物主人 | 我的宠物档案、预约下单（寄养/上门喂养/遛狗/洗护）、智能匹配、价格试算、看服务报告与遛狗轨迹、评价、优惠券、健康提醒 |
| SITTER 宠托师 | 上门喂养师/寄养师 | 接单大厅、我的订单、填写服务报告、遛狗轨迹打卡、我的排班、收入统计、评价查看 |

### 功能模块（15 个）
1. 用户与权限：注册/登录/JWT、三角色菜单与接口鉴权、个人中心。
2. 宠物档案：多宠管理、品种/性别/年龄/体重/绝育/疫苗/过敏史/性格/喂养习惯/定点医院。
3. 服务项目：上门喂猫、上门喂狗、上门遛狗、门店寄养、家庭寄养、洗护美容、陪玩、喂药护理，含计价方式（按次/按天）、基础价、时长。
4. 宠托师管理：资质认证状态、服务区域、擅长宠物、评分、接单量、可接单开关、排班。
5. 寄养空间：猫别墅/阳光犬舍/家庭寄养位等房型，总量/已占/价格/设施，入住占用可视化网格。
6. 预约订单（核心）：寄养（按天）与上门服务（按次/多日多次）统一订单；状态流 待确认→已确认→已接单→服务中→已完成，已取消/已退款；自动计价 = 基础价×天数(次数) + 附加服务 + 节假日系数(1.5) − 长住折扣(≥7天9折、≥15天8折) − 多宠折扣(第2只起8折) − 优惠券。
7. 入住管理：寄养订单的入住登记/退房结算，与寄养空间占用联动（入住+1、退房−1、防超卖校验）。
8. 服务报告：每次服务一张报告卡——喂食/换水/铲屎/陪玩/洗护清单打勾、食欲/精神/排泄状态、体温、照片 URL、备注；寄养每日日报同表承载。
9. 遛狗轨迹（特色）：轨迹点序列、距离/时长/配速，订单详情里 SVG 轨迹回放动画。
10. 智能匹配（特色）：按服务区域匹配 + 评分 + 擅长宠物品种 + 接单量 + 距离 打分，推荐 Top3 宠托师并给出推荐理由。
11. 价格试算器（特色）：选服务/日期/宠物数/附加项，实时算出明细（基础、节假日加价、折扣、券后价）。
12. 健康档案与提醒（特色）：疫苗/驱虫记录与下次到期日，30 天内到期自动生成提醒；体重记录与趋势折线。
13. 评价管理：订单完成可评（1–5 星+文字+标签），计入宠托师评分；管理员可隐藏违规评价。
14. 优惠券：管理员发放（满减/折扣），宠主领取、下单抵扣，状态 未使用/已使用/已过期。
15. 支付流水与公告消息：模拟支付/退款流水；平台公告、订单站内消息。

### 数据库（14 张表）
sys_user、pet、service_item、sitter_profile、boarding_space、booking_order、order_addon（订单附加服务，多对多明细可并入订单 JSON，二选一用明细表）、checkin_record、service_report、walk_track、health_record、review、coupon（+user_coupon 合并为 coupon 带 owner 字段亦可，设计用两表共 15 张亦可）、payment、notice、message。以 14–16 张为宜，种子数据要丰富：≥6 宠托师、≥8 宠物、≥10 服务项目、≥6 寄养空间、≥20 订单（覆盖各状态与近 30 天日期）、报告/轨迹/评价/健康/券齐全，保证大屏有真数据。

### 可视化设计
- 数据大屏/仪表盘（ECharts）：近 30 天订单量与营收双轴趋势、服务类型分布环图、寄养入住率仪表/柱状、宠物种类分布、宠托师接单 TOP5、订单状态漏斗/环图、好评率。
- 寄养空间占用：房型卡片网格 + 占用进度条 + 在住宠物列表。
- 预约日历：管理员/宠托师按月历查看每日订单数与明细。
- 轨迹回放：SVG 路径动画 + 里程/时长数据卡。

### UI 设计
暖橙宠物主题：主色 #f97316→#fb923c 渐变、奶油底 #fff7ed、圆角卡片、宠物 emoji/插画点缀；登录/注册页用 AI 生成的宠物寄养主题壁纸全屏背景 + 毛玻璃面板；侧边栏渐变 + 胶囊选中态；状态标签按订单流程配色；仪表盘欢迎横幅 + 图标统计卡。

### 演示账号
admin/admin123、owner/owner123（宠主，名下多只宠物与历史订单）、sitter/sitter123（宠托师，有待接/进行中订单）。另可注册新宠主。

## 三、验收标准
三角色登录与权限隔离正确；下单计价与手工核算一致；寄养入住不超卖；报告/轨迹/日历/大屏均渲染真实种子数据；智能匹配返回带理由的 Top3；构建一次通过、服务常驻、公网不动（仅本地 8082）。
